# 技術仕様書

## 1. テクノロジースタック

| 分類               | 選定                                                                          | 理由                                                                                     |
| ------------------ | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 言語               | TypeScript                                                                    | VSCode拡張開発の標準言語であり、型安全性を確保できる                                     |
| 実行環境           | VSCode Extension Host(Node.js)                                                | VSCode拡張として動作させるため                                                           |
| UIフレームワーク   | VSCode Extension API(`vscode`モジュール)                                      | TreeView、StatusBar、Commands、SecretStorage等、本ツールに必要なUI要素が標準で揃っている |
| ビルドツール       | esbuild                                                                       | 拡張のバンドルに十分な速度と設定のシンプルさ                                             |
| ローカルストレージ | JSONファイル(VSCode拡張専用ストレージ領域、`ExtensionContext.storageUri`配下) | 個人利用・単一ワークスペース規模のデータ量であればDB導入は過剰。またリポジトリの外に置くことで、誤ってGit管理下に入り社外/他メンバーと共有されるリスクをそもそも発生させない |
| シークレット管理   | VSCode SecretStorage API                                                      | Jira APIトークンを平文でファイルに残さないため                                           |
| Jira連携           | Jira Cloud REST API v3(`fetch`)                                               | 追加の重量な依存ライブラリを避け、Node.js標準の`fetch`で完結させる                       |
| Lint / Format      | ESLint / Prettier                                                             | コード品質の一貫性を保つ                                                                 |
| テスト             | `@vscode/test-electron`(拡張機能結合テスト)、Vitest(純粋ロジックの単体テスト) | UI連携が必要な部分と、アンカー解決・要約生成ロジックなど純粋な処理を分離してテストする   |
| パッケージング     | `@vscode/vsce`                                                                | `.vsix`形式でのローカルインストールを想定(Marketplace公開は将来検討)                     |

## 2. 開発ツールと手法

- バージョン管理はGitを使用する。個人開発のため、複雑なブランチ戦略は取らずmainブランチ中心の運用で良い
- コーディング規約・命名規則は`development-guidelines.md`で別途定義する
- コミット前にlint・型チェック・テストを実行することを推奨する(CIの導入は必須要件としないが、後から追加しやすい構成にしておく)

## 3. 技術的制約と要件

- 対応VSCodeバージョンは`^1.85.0`以上を最低要件とする(TreeViewのドラッグ&ドロップAPI、SecretStorage API、Node.js標準`fetch`が安定して利用できるバージョン)
- Jira連携はJira Cloud REST API v3を対象とする(利用環境がJira Cloudであることを確認済み)。Jira Server/Data Centerは対象外とする
- ログ記録・タスク化・タスクツリー操作はすべてローカルで完結し、ネットワーク接続を必要としない。ネットワークが必要なのはJiraへの要約push・チケット存在確認のみに限定する
- マーカーはMarkdownコメント構文(`<!-- tasklog:{id}:start -->` / `<!-- tasklog:{id}:end -->`)を用いる。他のMarkdownツールでの表示・プレビューを壊さない構文であることを条件とする
- タスクメタデータは`ExtensionContext.storageUri`配下に保存し、ワークスペース(リポジトリ)のディレクトリ配下には一切配置しない。これにより`.gitignore`の設定漏れによる誤コミット・社外/他メンバーへの意図しない共有を構造的に防ぐ
- タスクメタデータの書き込みは、一時ファイルへの書き込み後にリネームする方式(アトミックな書き込み)とし、VSCodeやOSのクラッシュ時にファイルが破損した状態で残らないようにする
- 同一ワークスペースを複数のVSCodeウィンドウで同時に開いた場合の排他制御は行わない(個人の単一ウィンドウでの利用を前提とする)。同時に開いた場合は後勝ち(last write wins)となることを既知の制約として明記する
- Jira接続情報のうち、秘密情報でないもの(インスタンスURL・メールアドレス)は通常の拡張設定(`contributes.configuration`)で管理し、SecretStorageに保存するのはAPIトークンのみに限定する

## 4. パフォーマンス要件

- ログファイルは個人の作業ログという性質上、数千行程度までを主な利用規模と想定する。ファイルを開いてからタスクツリーが表示されるまで、体感的な遅延(概ね1秒以内)がないこと
- 停滞検知のための定期チェックは、エディタの操作性に影響を与えない頻度(例:1分間隔程度)で行う
- カーソル移動など高頻度に発生するイベントに反応する処理(ツリーハイライト等)は、軽くデバウンス(例:150ms程度)し、キー入力・カーソル移動のたびに重い処理が走らないようにする
- タスク数が数百件程度になっても、タスクツリービューの描画・親子関係変更が実用上問題ない速度で動作すること
