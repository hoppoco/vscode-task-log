# 初回実装(Phase 1)要求

## 位置づけ

`docs/`で設計した全機能のうち、まず「ログ記録 → 参照型タスク化 → タスクツリー表示」というコア体験のみを実装し、日常の調査作業で実際に使いながら検証する。停滞検知・Jira連携は本Phaseのスコープ外とし、コア体験の実用性を確認した後、別のsteeringディレクトリで追加実装する。

## 変更・追加する機能の説明

- VSCode拡張のプロジェクト初期セットアップ(`package.json`、`tsconfig.json`、`esbuild.js`、Lint/Format設定)
- ログファイル内のテキスト選択範囲から、開始・終了マーカーを挿入してタスクを作成する機能(`taskLog.createTaskFromSelection`)
- タスクのタイトルをインライン入力(自動提案+その場編集)で確定する機能
- タスクメタデータを拡張専用ストレージ(ワークスペースごとに分離)へ永続化する機能
- サイドバーにタスクツリー(親子構造)を表示する機能
- タスクの親を変更する機能(`taskLog.setParent`)
- タスクにフォーカスを設定・解除し、ステータスバーにパンくずを表示する機能(`taskLog.setFocus` / `taskLog.clearFocus`)
- タスクのステータスを「未完了 / 完了」に変更する機能(`taskLog.markDone`)
- マーカーが欠落した場合に「アンカー未接続」状態として識別できる機能

### Phase 1中に実機確認を経て追加した機能

当初の`docs/functional-design.md`ではコマンド一覧に含まれていなかったが、実機で使ってみたところ基本的なCRUD操作として不可欠と判明し、Phase 1のスコープに追加した。

- ログ編集中、マーカー範囲の直上に対応するタスク名をCodeLensで表示し、クリックでフォーカスする機能(編集中にどのマーカーがどのタスクか分からないという問題への対応)
- アンカー未接続になったタスクのアンカーを、新しい選択範囲に張り替える機能(`taskLog.reanchorTask`)
- タスクを削除する機能(`taskLog.deleteTask`)。ログ本文・マーカーには一切触れない。子タスクがある場合は「昇格」か「再帰削除」かを実行時に選択する
- タスク選択UI(QuickPick)で、同名タスクを区別するための短縮ID表示

## 今回含めない機能(Phase 2以降)

- 停滞検知(`StallDetector`)
- 要約生成(`SummaryGenerator`)
- Jira連携全般(`JiraClient`、`taskLog.linkJiraIssue`、`taskLog.pushSummaryToJira`、`includeInAncestorSummary`)

## ユーザーストーリー

- 調査対象のコードで問題を発見したとき、作業を止めずにその場でログに書き留めたい
- 書き留めた内容の一部が「これは後で検証が必要」と思ったとき、選択してワンアクションでタスクとして切り出したい
- 複数階層にわたって派生した調査について、今どこにいるか・元は何を解決しようとしていたかを、いつでも一目で確認したい

## 受け入れ条件

- ログの記入形式に一切の制約がないこと(拡張は選択範囲へのマーカー挿入以外、ログ本文に介入しない)
- テキスト選択からタスク化までが1操作(ショートカットまたはコマンド)で完結すること
- タスク化してもログ本体のテキストは移動・削除されないこと(マーカーの挿入のみ)
- タスクツリーの親子関係を、作成後いつでも変更できること
- マーカーが削除・欠落したタスクが、ツリービュー上で「アンカー未接続」として識別できること
- アンカー未接続のタスクを、新しい範囲を選択してアンカーを再設定できること
- タスクを削除できること。削除してもログ本文・マーカーは変更されないこと。子タスクがある場合は昇格・再帰削除を選べること
- 拡張機能を`.vsix`としてローカルにインストールし、実際のVSCode上で一連の操作(タスク化→ツリー確認→親子変更→フォーカス→削除)が行えること

## 制約事項

- `docs/architecture.md`・`docs/functional-design.md`・`docs/repository-structure.md`・`docs/development-guidelines.md`で定めた技術選定・設計・規約に従う
- Jira連携が前提となる機能(要約push、Jiraキー紐付け)は実装しない。データモデル上の`jiraIssueKey`・`includeInAncestorSummary`フィールドは用意するが、値を設定・利用する機能は次のPhaseで実装する
