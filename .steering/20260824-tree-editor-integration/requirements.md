# タスクツリー・エディタ連携強化 要求

## 位置づけ

Phase 1で構築したコア体験(ログ記録・参照型タスク化・タスクツリー表示)に対し、実際に使う中で挙がった操作感の要望に応える。Jira連携(Phase 2として計画していたもの)より優先度を上げ、ローカルでのタスク管理の使い勝手を先に改善する。

## 変更・追加する機能の説明

- タスクツリーの項目に、ステータス(オープン/クローズ)を切り替えるインラインアクションボタンを追加する
- タスクツリーの項目をクリックすると、対応するログの該当マーカー範囲をエディタで開く
- タスクツリーの項目のタイトルに、そのタスクが属するログファイル名を付記する
- タスクツリー上でドラッグ&ドロップして、タスクの親を変更できるようにする(兄弟間の並び替えは対象外)
- カーソル位置に対応するタスクツリー項目を自動的にハイライト(reveal)する。これは表示のみの機能とし、フォーカス(新規タスク作成時の親のデフォルト)には影響させない
- カーソル位置に対応するタスクのステータスを、コマンド一つでオープン/クローズできるようにする
- カーソル位置に簡単にタスクを作成できるようにする(選択範囲が無い場合は現在行を対象にする)
- 選択範囲が既存タスクのマーカー範囲に含まれる場合、新規タスクの親のデフォルトをその既存タスクにする(タスク化を実行した瞬間の一回限りの判定とし、継続的に追従する仕組みにはしない)

## 検討した上で見送るもの

- **フォーカスのカーソル自動追従**:ドキュメント上のマーカーの物理的な入れ子と、タスクツリー上の論理的な親子関係は、意図的に独立して変更できるモデルにしている。フォーカスをカーソル位置(=物理的な入れ子)に自動追従させると、エディタ自体が「もう一つの暗黙のツリー」として機能してしまい、`setParent`で親子関係を変更した後にツリーとエディタの表示が食い違う場面で混乱を招く。カーソル位置の活用は「表示のハイライト」に留め、状態を駆動する「フォーカス」の概念とは切り離す
- **タスクツリーでの兄弟間の並び替え**:現在のデータモデルには兄弟の表示順という概念が無く、親子関係(構造)とは別に「順序」フィールドを新設する必要がある。優先度が低いため今回は見送る

## ユーザーストーリー

- タスクツリーの項目をひと目見て、それがどのファイルの話か分かるようにしたい
- ツリーの項目をクリックして、すぐに該当箇所のログを見に行きたい
- ツリー上でステータスを素早く切り替えたい(コマンドパレットを介さず)
- 今エディタで見ている場所が、ツリー上のどのタスクに対応するか、常に分かるようにしたい
- タスクの親子関係を、コマンドではなくドラッグ操作で直感的に変更したい
- 調査を続けている最中に、いちいちQuickPickでタスクを選ばなくても、今書いている場所に紐づくタスクをサッと作成・操作したい

## 受け入れ条件

- タスクツリーの項目にインラインボタンがあり、クリックでステータスが切り替わること(コマンドパレットを介さない)
- タスクツリーの項目(インラインボタン以外の部分)をクリックすると、対応するログのマーカー範囲がエディタで開かれ、該当箇所にカーソルが移動すること
- タスクツリーの項目に、ログファイル名が表示されていること
- タスクツリー上でドラッグ&ドロップにより親を変更できること。兄弟間の並び替えは実装しないこと
- カーソルを異なるマーカー範囲に移動すると、タスクツリー上の対応する項目が自動的にハイライトされること。この操作によってフォーカス(新規タスク作成時の親のデフォルト)が変化しないこと
- カーソル位置に対応するタスクのステータスを切り替えるコマンドが実行できること
- 選択範囲が無い状態でタスク作成コマンドを実行すると、現在行を範囲としてタスクが作成されること
- 既存タスクのマーカー範囲内で新規タスクを作成すると、そのタスクが自動的に親として設定されること。その後`taskLog.setParent`で変更しても、他のタスクの動作に影響しないこと

## 制約事項

- `docs/development-guidelines.md`のDIパターン・エラー処理規約・破壊的操作の扱いに従う
- 既存のPhase 1機能(マーカー未接続表示、CodeLens、削除、アンカー再設定)の挙動を壊さない
- 実装により`docs/functional-design.md`等の永続的ドキュメントに影響する場合は、該当ドキュメントを更新する
